# Cashbook

Система учёта личных финансов: наличные, банковские и криптовалютные счета, транзакции, долги и подробная аналитика.
Работает полностью в браузере и хранит данные в вашей собственной Google-таблице, по желанию в зашифрованном виде.
Версия **1.0.0**. Языки интерфейса: украинский, английский, русский. Светлая и тёмная тема, ПК и телефон.

- **Сущности:** активы (валюты и токены), финансовые сервисы (банки, биржи, кошельки), контакты (включая ваш собственный), счета, двухуровневые категории, транзакции, долги.
- **Транзакции** проходят только между счетами одной формы хранения средств. Одна из сторон может быть не указана. Комиссия платится отправителем сверх суммы, у криптосчетов возможна в другом активе.
- **Долги** между любыми двумя контактами. Сумма меняется только привязанными транзакциями: погашение или новая выдача. Долг можно создать прямо из формы транзакции.
- **Балансы, обороты и статистика никогда не хранятся.** Они вычисляются из записей при каждом изменении, поэтому рассинхронизация невозможна.
- **Аналитика:** доходы и расходы, категории (родительская категория включает дочерние), динамика капитала и сравнение дат, счета и сервисы, рейтинг контрагентов, комиссии, долги, календарь активности. Для всего доступны период (день, неделя, месяц, год, произвольный), выбор счетов и десяток фильтров.
- Поиск без учёта регистра с подсветкой совпадений, мультиселект-фильтры, пагинация.

Стек: Vite + React + TypeScript, Recharts, Google Identity Services + Sheets API v4, WebCrypto.
Бэкенда нет: приложение обращается к Google напрямую из браузера.

## Шифрование

При подключении пустой таблицы Cashbook предлагает включить шифрование (рекомендуется) и задать ключ: 4–20 символов, только латинские буквы и цифры.

- Ключ шифрования выводится из пароля через **PBKDF2-SHA256** (600 000 итераций, случайная соль), шифр **AES-256-GCM** (WebCrypto).
- Каждая строка таблицы шифруется отдельно: JSON-запись сущности превращается в одну ячейку `c1.<base64>` со случайным IV. Имя листа используется как AAD, поэтому строку нельзя незаметно перенести на другой лист.
- Ни пароль, ни ключ не попадают в таблицу. В листе `Meta` лежит контрольное значение, по которому проверяется, подходит ли введённый ключ. **Потерянный ключ означает потерянные данные.**
- После ввода ключ хранится в этом браузере, поэтому перезагрузка и новые вкладки его не спрашивают. Хранится он в IndexedDB как неизвлекаемый `CryptoKey`: его байты недоступны никакому скрипту. Пока открыта хоть одна вкладка приложения, запись продлевается. Через час без продления (все вкладки закрыты, браузер упал) запись считается мёртвой и удаляется при следующем запуске. Выход из аккаунта, отключение таблицы или шифрования и неподходящий ключ удаляют её сразу.
- Шифрование можно включить или отключить позже в **Настройки → Структура таблицы**. Включение проходит тот же путь с предупреждением, согласием и вводом нового ключа дважды. Для отключения нужно ввести текущий ключ. Все записи переписываются в новом формате одним запросом вместе с `Meta`. Чтобы сменить ключ, отключите шифрование и включите его снова с новым ключом.
- Если формат сменили на другом устройстве, остальные устройства не смогут записать строки в старом формате. Перед каждым сохранением приложение сверяет `Meta`, при расхождении отказывается писать и предлагает перезагрузить данные.

## Структура таблицы

| Лист           | Содержимое                                                                                           |
|----------------|------------------------------------------------------------------------------------------------------|
| `Meta`         | `key`, `value`: приложение, версия схемы, параметры шифрования                                        |
| `Assets`       | `id, name, description, code, symbol, image, decimals, forms, createdAt, updatedAt`                  |
| `Services`     | `id, name, description, image, forms, order, createdAt, updatedAt`                                   |
| `Contacts`     | `id, name, description, image, isSelf, createdAt, updatedAt`                                         |
| `Accounts`     | `id, name, description, form, assetIds, initialBalances, requisite, contactId, serviceId, createdAt, updatedAt` |
| `Categories`   | `id, name, description, image, parentId, order, createdAt, updatedAt`                                |
| `Transactions` | `id, date, fromId, toId, assetId, amount, fee, feeAssetId, categoryId, debtId, description, createdAt, updatedAt` |
| `Debts`        | `id, name, description, assetId, debtorId, creditorId, amount, createdAt, updatedAt`                 |

В зашифрованной таблице у каждого листа данных одна колонка `data`.
Сущности связаны между собой только через `id`. Формы хранения средств (`cash`, `bank`, `crypto`) зашиты в приложение.

Запись идёт построчно: изменённая сущность перезаписывает только свою строку, новая занимает свободную строку, удалённая очищает свою (пустые строки потом переиспользуются). Поэтому сохранение остаётся быстрым даже при многолетней истории.

При каждой загрузке проверяется целостность: заголовки, расшифровка каждой строки, типы значений, уникальность `id` и все ссылки между сущностями. Найденные проблемы показываются с указанием листа и строки.

**Версии.** В `Meta` хранится версия схемы данных. Если таблица создана старой версией приложения, её записи проходят цепочку миграций из `src/lib/migrations.ts`, после чего таблица переписывается в актуальном формате. Таблицу от более новой версии приложение не открывает.

## Настройка Google Cloud (один раз)

1. Откройте <https://console.cloud.google.com/> и создайте проект (например, `Cashbook`).
2. **APIs & Services → Library**: включите **Google Sheets API**.
3. **Google Auth Platform → Branding**: название `Cashbook`, ваш email. Audience: **External**.
4. **Audience → Test users**: добавьте аккаунты, которые будут пользоваться приложением.
5. **Data access**: добавьте scope `https://www.googleapis.com/auth/spreadsheets`.
6. **Clients → Create client**, тип **Web application**. Authorised JavaScript origins:
   - `https://kibergod.github.io`
   - `http://localhost:5173` (для локальной разработки)

   Скопируйте **Client ID**. Секретного ключа в этой схеме нет.

## Локальная разработка

```bash
npm install
cp .env.example .env.local      # .env.local игнорируется git
# впишите Client ID в .env.local: VITE_GOOGLE_CLIENT_ID=...
npm run dev
```

Генератор тестовых данных (полгода активности) лежит в `dev-local/seed.ts`. Эта папка в `.gitignore` и в репозиторий не попадает.
Если файл есть, в **Настройки → Разработка** появляется кнопка «Заполнить тестовыми данными». Она заменяет всё содержимое подключённой таблицы, поэтому используйте её только на отдельной тестовой таблице.

## Публикация на GitHub Pages

1. **Settings → Secrets and variables → Actions → New repository secret**: `VITE_GOOGLE_CLIENT_ID` = ваш Client ID.
2. **Settings → Pages → Source: GitHub Actions**.
3. Push в `main`: `.github/workflows/deploy.yml` соберёт и опубликует сайт на `https://kibergod.github.io/cashbook/`.

Репозиторий должен быть публичным (бесплатный GitHub Pages).

## Особенности

- Google выдаёт доступ примерно на час. После этого приложение попросит нажать «Продолжить с Google»; несохранённые изменения не теряются.
- При одновременной правке с двух устройств сохраняется последняя запись. Данные перечитываются, когда вы возвращаетесь на вкладку спустя минуту и больше.
- Не редактируйте листы вручную: это может нарушить структуру, а в зашифрованной таблице сделать строки нечитаемыми.
